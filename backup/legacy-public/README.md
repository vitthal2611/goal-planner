# Legacy Public Folder Backup

**Date:** March 24, 2026

## What's in this folder?

This folder contains the old standalone HTML/CSS/JS implementation that was previously in the `/public` folder before the React migration.

## Files moved:

- `index.html` - Old standalone HTML file (6106 lines with inline styles/scripts)
- All associated CSS files (design-system.css, habit-*.css, etc.)
- All associated JS files (firebase-service.js, data-manager.js, etc.)
- Additional HTML templates (mobile-clean-example.html, mobile-first-template.html)

## Why were these moved?

1. **Project now uses Vite + React** - The application has been migrated to a modern React setup
2. **Root index.html is the entry point** - Vite uses `/index.html` (in root) as the entry point, not `/public/index.html`
3. **Public folder purpose changed** - In Vite, the `public` folder should only contain static assets (images, fonts, etc.) that are copied as-is to the build output
4. **These files were not being used** - The legacy files were leftover from the old implementation and were not part of the build process

## Current project structure:

```
/index.html          → Vite entry point (references /src/main.jsx)
/src/                → React components and application code
/public/             → Static assets only (now empty, ready for images/fonts)
/dist/               → Build output (generated by Vite)
```

## Can these be deleted?

Yes, once you've confirmed the React application works correctly in production, these legacy files can be safely deleted. They are kept here as a backup for reference only.

## Restoration (if needed):

If you need to restore these files for any reason:
```bash
cp -r backup/legacy-public/* public/
```

However, this would revert to the old standalone implementation and break the React build process.
